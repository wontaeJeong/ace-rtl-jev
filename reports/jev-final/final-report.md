# ACE-RTL JEV-like 최종 제한 예산 검증 보고서

**범위:** 기존 292-케이스 기준 실행 재사용, 판단 지점 48개 + 실제 CVDP 1개 E2E. 전체 292개 개선 버전 평가는 실행하지 않았다.
**결과를 구분한다:** 판단 API 비용 실험은 전체 RTL 성공률 실험이 아니다. 1-케이스 결과는 일반화·통계적 우위를 입증하지 않는다.

**핵심 결론:** 소규모 실측은 전체 JEV 기본 적용의 개선을 입증하지 않는다. 실측 케이스 토큰 45979 → 50269 (+9.33%), 평균 케이스 시간 43.794 → 65.415 s. 실제 주력 모델 대체 호출 1회. 원래 배치 동시 실행 조건이 달라 시간 차이를 통제된 속도 차이로 해석하지 않는다.
판단 감사는 48회 중 45개 스키마 유효 /3개 판단 오류, 수용 13개 /대체 호출 필요 35개였다. 옛 주력 모델 문장 휴리스틱과 19개 중 1개 일치(정답 기준 아님), 공식 전체 통과 12개 중 12개 해결로 판단했다. 수용 부분집합 토큰 감소만으로 전체 최적화를 주장하지 않는다.
수용 판단 13개 중 11개는 이미 공식 평가기가 전체 통과인 상태였다. 따라서 단순히 성공을 확인하는 데 모델을 쓰지 않는 결정적 종료 상태 처리부터 오프라인 검토할 가치가 있다. 해당 개선은 이번에 구현/추가 실험하지 않았으며 절감을 실제 성과로 계산하지 않는다.
따라서 기준 실행을 기본으로 유지하고 JEV 경로를 실험적으로 선택 활성화하는 경로로 둔다. 남은 예산을 이유로 재시도·추가 평가군을 실행하지 않았다.

JEV는 제한된 상태와 유한한 선택지 출력만 사용한다. 기존 주력 LLM의 풍부한 변경 분석/설명과 정보량이 같지 않으므로 토큰 감소에는 정확도·정보 손실 상충 관계가 있다.
수용 판단 부분집합 토큰 감소율 (%)는 **확신 기준을 통과한 판단 부분집합만의** 원본 기록 대비 실제 JEV 토큰 감소이며 전체 에이전트 절감률이 아니다. 실패·불확실 판단의 실제 JEV 비용은 모두 포함했다.
주력 모델 대리 지표 일치는 추출한 옛 주력 모델 문장과의 휴리스틱 일치이며 정답 기준이 아니다. 전체 통과 부분집합에서는 공식 평가기가 통과한 경우 해결 판단인지 제한적으로 확인했다.
감사 단계에서는 추가 주력 대체 호출을 구매하지 않았다. 대체 호출 필요 판단과 실제 대체 호출을 혼동하지 않는다. 다음 값은 실제 지출이 아닌 **원본 대체 호출 토큰을 재사용한 시나리오 추정**이다:
`hypothetical_tokens_with_historical_fallback = 629153`.

## 한계

비에이전트 방식·비상용 도구의 제한된 네이티브 평가군 한 묶음으로, 모든 CVDP 작업 흐름이나 원래 기본 예산을 포괄하지 않는다. 실제 도구 요구에 따라 상용 도구가 필요한 항목을 명시적으로 제외했다. API의 확률적 변동과 원격 지연은 통제하지 못했으며, 단일 실행 차이는 관찰 결과일 뿐 통계적으로 입증된 효과가 아니다. 반복·요소 제거 실험은 실제 실행한 경우에만 보고해야 한다. 출처·무결성 규칙·남은 작업은 환경 및 개선 기회 문서를 참고한다.


## 3. 비용 제어와 원본 보존

주력 API 12회/예약 300,000 토큰, JEV 64회/예약 1,000,000 토큰/USD 0.10 노출 한도. 공유 SQLite가 준비 실행·재시도·실제 대체 호출까지 포함한다. 리디렉션 재전송을 차단하고, 토큰 정보 없는 실패도 예약을 유지하며, 답변이 잘못돼도 유효한 USD 영수증은 정산한다.
입력 UTF-8 바이트 + 래퍼·출력 여유분 예약은 불투명한 제공자의 절대 요금 보증이 아니다. 주력 가격 API는 모델 식별자만 제공하여 정확한 주력 USD와 전체 비용을 만들지 않았다. JEV USD 영수증은 OpenRouter 공식 문서로 확인했다. 서버측 사용 한도가 필요하면 운영자가 설정해야 한다.
기준 실행은 다시 실행하지 않았다. 292-케이스 정리된 기준 실행은 239 성공 / 52 실패 / 1 시간 초과, 4,367.250 s, 알려진 16,538,281 토큰 +33 사용량 미확인 호출로 보존돼 있다.

## 4. 해석·한계·후속 방향

1-케이스 E2E에서 토큰이 늘거나 지연이 증가하면 그대로 보고한다. 원래 292-케이스 배치와 달리 새로운 한 케이스만 실행했으므로 과거 케이스별 시간 차이를 통제된 배치 속도 개선으로 주장하지 않는다.
판단 실패/낮은 확신도/낮은 대리 지표 일치가 많으면 원래 주력 경로를 유지하는 것이 합리적이다. 코드 생성과 깊은 수정 추론은 대체하지 않았다. 비용이 남았다는 이유로 추가 실험을 임의로 확대하지 않는다.
추가 설계: 목표 오류 식별과 보고서 압축 품질을 먼저 오프라인 보완하고, 더 큰 짝지은 평가군/반복/요소 제거 실험은 별도 예산을 정한 뒤 수행한다. 현재 그런 실험은 미실행이다.
