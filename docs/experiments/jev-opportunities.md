# JEV-like opportunity audit

Status: **source/API analysis only**. Full baseline is still running. No optimization hook has been applied; implementation is gated on baseline completion. The choices below are proposed, not measured benefits.

## Confirmed SystemOne capabilities

Official source: Ollama `docs/capabilities/decision.mdx` and `decision/types.go`, retrieved via Context7. A real POST to the initially configured `/v1/systemone` succeeded. User subsequently updated `.env.local` to bearer-authenticated `typesafe/jev-1.13` at `/api/alpha/decisions`. A second real POST succeeded with the same decision request/answer schema; current implementation must use **the updated endpoint**, not a guessed Ollama path. See `experiments/preflight/jev-updated-warmup.json`; provider cost is now also returned and should be retained. Local Ollama loading properties cannot be attributed to this updated hosted provider.

Request: `model`, string/object `state`, named `questions`. A `choice` question has `instructions` and 2–26 named `criteria` with descriptions. Response: named `answers` with `type=choice`, selected `choice`, option probabilities and confidence [0,1]. Usage is **input_tokens/output_tokens**, not primary API's prompt/completion fields. Live fixture is in `experiments/preflight/systemone-warmup.json`. Do not assume free-form reasoning, tool execution, arbitrary generated RTL, streaming, Chat Completions, persistent model-cache control or deterministic seed support for this endpoint.

Implementation should support only the validated `choice` shape initially. Validate label membership, probability map completeness and finite [0,1] values, distribution sum within tolerance, finite confidence, usage nonnegative integers and all requested named answers. Confidence threshold and timeout should be explicit policies. Validation/model failures must delegate to the original primary LLM path; count both JEV attempt and primary fallback costs. Do not mark a candidate pass based on any model decision.

## Proposed limited implementation

1. Baseline remains entirely primary/deterministic original behavior (plus necessary common API/venv compatibility fixes).
2. One hook in retrospective effectiveness only, gated by explicit experiment mode. Do not intercept all adapter prompts by fuzzy textual matching.
3. Independent `systemone_adapter.py` owns HTTP, validated choice schema and JEV event recording; original code owns reasoning and fallback.
4. Supply only prior focused error, applied guidance, bounded real evaluator diagnostics and public generated-code changes; no private test/scorer source.
5. Selected label is converted into a short factual effectiveness sentence; code changes are summarized by deterministic diff. Keep history record and original generator/reflector inputs otherwise intact.
6. On low confidence, unknown label, malformed response, timeout or unsupported model, call the original retrospective primary method and mark a counted fallback. No false claim that local fallback has zero overhead.
7. Warm both models by real inference; no custom response cache. Match original baseline IDs and budgets. Report JEV/primary calls, tokens and latency separately, including failures.

## Evaluation and ablation

Main comparison must include total JEV overhead and success-rate change, not only displaced primary tokens. Case-level matched outcomes and actual unknown usage matter. Single-hook design's baseline vs improved contrast is the hook ablation; further repetitions and point-wise factorial experiments require actual extra runs and cannot be implied by source inspection. Provider/model cache and stochasticity remain limitations unless repeat measurements are completed.
